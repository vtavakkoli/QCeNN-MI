# Simulator-to-hardware protocol

A2–A4 are implemented as small **hybrid** experiments. Optimizer objectives,
matrix products, scales, prediction and polynomial corrections run classically.
Local state preparation, measurement and the small dense A4 polynomial dilation
are quantum circuits. The polynomial/dilation matrices are constructed classically. No runtime service,
credentials or paid hardware job is invoked automatically.

## Reproduce simulator checks

Install `pip install -e '.[dev]'`, then run `pytest -q` and
`python -m qcenn_mi.experiments`. Results include software versions, seed,
noise probability, matrices, fitted parameters, tomography diagnostics, compiled
gate counts/depths, warm/cold solve evaluation counts and separate residuals.
The reported safeguarded classical correction must never be attributed to quantum accuracy.
The separate A4 quantum dilation checks have their own residuals and postselection data.
QPY files are regenerated by the campaign and uploaded as CI artifacts; JSON and
Markdown reference evidence is committed in `results/a2-a4/`.
Full tomography projects a noisy mixed state onto its principal real eigenvector;
raw density purity and minimum eigenvalue are reported because shot estimates
can be nonphysical. Tomography is not scalable and assumes real ideal states.

## Prepare a physical experiment

1. Choose an accessible backend and record backend identity, date, calibration,
   native gates, coupling map, shot budget and provider/runtime versions.
2. Load a QPY preparation circuit from the campaign, or use a fitted result's
   `circuits()`. These have no measurements and contain no hardware credentials.
3. For a backend supporting Qiskit's `Backend.run`, pass it explicitly to
   `CoupledResult.measure(backend=backend, shots=8192, audit=records)`
   with `records=[]`. It transpiles and executes
   the full Pauli measurement set. This call submits real jobs when given a real
   backend. Providers supporting only runtime primitives need a provider-specific
   adapter; that integration has not been tested here.
4. For each 4×4 solve budget 4 columns × 9 settings × shots, plus any repeats;
   each 2×2 solve uses 2 × 3 settings × shots. Transpilation can add routing gates.
5. Retain provider job IDs, raw counts, transpiled circuits, layouts, calibration
   snapshots and result JSON. The optional `audit` list captures job IDs, raw
   counts, retained shots and compiled resource counts; serialize it to JSON.
   Archive transpiled circuits/layouts and calibration using provider tooling.
   A4 polynomial circuits include an extra ancilla. `PolynomialResult.measure`
   performs ancilla=0 postselection and returns measurement audit records.
   Budget at least the same settings/shots plus the postselection overhead;
   inspect retained shots rather than assuming unit success probability.
6. Repeat at multiple seeds/shots and depths; report residual distributions and
   uncertainty. Compare ideal, finite-shot, noise-model and actual hardware data
   without applying classical correction to only one comparison arm.
7. Only mark A5 complete after actual successful QPU execution and calibration
   analysis. A simulator PASS alone does not establish hardware performance.

## Acceptance and limitations

Default campaign gates: ideal residual <1e-7, shot residual <0.15, synthetic-noise
residual <0.25, corrected tracking residual <1e-8, and correction must not worsen
noisy residuals. These gates apply to the named fixtures with 8192 shots and
synthetic error probability 0.002. They are not universal hardware thresholds.
The optional depth sweep up to 150 layers can be expensive and can fail; failures
must remain visible. Matrices must be finite, real, nonsingular and 2×2 or 4×4.
Ill-conditioned matrices and sudden changes can defeat the solve budget.

A2 shares template parameters across columns within a time step, not across
unrelated matrices. A3 carries those parameters between consecutive time steps;
its classical predictor is a separate path, not quantum state memory.
A4 includes both a safeguarded Neumann/Newton-Schulz-style classical polynomial
and an ancilla-based dense quantum dilation. The dense dilation is compiled from
a classically computed polynomial, not an efficient quantum polynomial synthesis
algorithm. Scalable block encoding, scaling studies and quantum advantage remain
open work. The A4 ideal path restores amplitude magnitude using the dilation
normalization; the finite-shot path refits classical least-squares column scales.
These are separate checks and should not be treated as identical procedures.


## Larger block-hybrid checks

`python -m qcenn_mi.scaling` tests symmetric/nonsymmetric 10×10 and 100×100
fixtures, both with ideal and 4096-shot quantum 2×2 diagonal-block seeds.
Full-matrix correction is classical, including every cross-block coupling.
The amplitude-encoded circuit solver and dense quantum dilation remain limited
to 2×2/4×4; no 100-dimensional quantum state solve is asserted. Diagonal-block
invertibility and convergence are required and explicitly checked. The generated
`results/scaling/result.json` includes per-block residuals and correction history.
A separate dynamic 2×2 trajectory changes all matrix entries over a full period
and verifies warm-started circuits using finite-shot readout at every time point.
